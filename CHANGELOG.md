# Changelog

## Unreleased

## v0.4.0 - 2026-11-05

- Add the Apache-2.0 `LICENSE`, `SECURITY.md` and `CONTRIBUTING.md`.
- README: list `proxmox` and `notify` in the package table.
- Every exported name now has a doc comment, and comments, tests and docs are product-neutral.
- **Behavior change:** `dockerhost` compose-scan helper containers are now named `keel-compose-scan-<n>` instead of `ballast-compose-scan-<n>`. Anything that matches the old prefix (for example Ballast tests or cleanup scripts) must be updated. No exported Go API changed.

- `dockerhost`: a failed compose scan now removes its helper container with `--volumes`, within a 30-second limit, so a helper image that declares a volume cannot leak it. A failed removal is added to the returned error. No API change.
- Add `proxmox`, moved from Ballast's `internal/proxmox` (`client.go`, `proxmox.go`, `resolve.go` and their tests); the backup-specific files (`vzdump`, `snapshot`, `drill`, `space`) stay in Ballast. New: exported `Client.Do` (so products build their own endpoints on the client), and firewall endpoints in `firewall.go`: `ListNodeGuests` (`/nodes/{node}/qemu|lxc`), `Scope` (cluster/node/qemu/lxc) with `FirewallOptions`/`SetFirewallOptions`, `FirewallRules`/`AddFirewallRule`/`DeleteFirewallRule`, `SecurityGroups`/`SecurityGroupRules`, `IPSets`/`IPSetEntries`, `Aliases`. **Breaking for Ballast's migration:** `DefaultCredentialName` is now a function, `DefaultCredentialName(product)` (Ballast passes `"ballast"`); the 401/403 message no longer names the `VM.Backup` permission; Ballast's vzdump/snapshot/space/drill code must call `Client.Do` instead of the unexported `do`/`get`.
- Add `notify`, the generic channel half of Ballast's `internal/notify` (ballast `notify.go`, `email.go` and their tests): `Channel`, `Event`, `Notifier` (with `ErrNoChannels` and `Resolve`), `NtfyChannel`, `WebhookChannel`, `EmailChannel`, plus new `DiscordChannel` and `SlackChannel`. Ballast's engine/freshness/scheduler coupling, cron max-age code, digest/job formatters, tiers and DB-backed channel config stay in Ballast. **Breaking for Ballast's migration:** `Event.Tier`, `TierName`, `ForTier`, `SendTiers` and the `Format*` helpers are not in keel (keep them in Ballast, wrapping `notify.Event`); ntfy titles come from `Event.Title` (Ballast sets "Ballast test notification" etc.; otherwise `[service] type`); the webhook signature header is `WebhookChannel.SignatureHeader` (default `X-Signature`; Ballast must set `X-Ballast-Signature`); `EmailChannel.Product` supplies the subject prefix (`"Ballast"` keeps `[Ballast]`) and the "Backup copy" body line is gone; the event-type constants other than `EventTest` stay in Ballast; `ErrInvalidChannel` now lives in keel.

- Add `dockerhost`, moved from Ballast's `internal/dockerhost` (ballast commit 6fe6639) with its tests. It is decoupled from Ballast's restic `backend` package: SSH key validation now comes from the new `sshkey` package. **Breaking for Ballast's migration:** `DefaultCredentialName(host)` is now `DefaultCredentialName(product, host)`. Ballast must pass `"ballast"` to keep its existing credential file names (`ballast-dockerhost.<host>`). User-facing messages no longer name Ballast (for example, "not installed on this machine" instead of "on the Ballast machine"), so Ballast tests that match those strings need updating.
- Add `sshkey.Render`, moved from the SSH branch of Ballast's `backend.RenderCredentials`, together with `opensshEncrypted` and its tests. The passphrase error message is now product-neutral. Ballast's `backend` can call it once it migrates.
- Initial extraction of `secret` and `runner` from Ballast (commit 8add0bc of ballast), with import paths changed to `github.com/springledev/keel/...` and product-specific comments generalized.
